# P2-002 — Council Run Persistence & History

Версия: **v0.6.1**
Alembic revision: **`20260716_0044`**

## Результат

Каждый запуск AI Council теперь сохраняется после завершения, включая:

- исходный вопрос, режим и состав;
- ответы или ошибки участников;
- фактически использованные fallback-модели;
- latency и token usage, если их вернул provider;
- итоговый синтез, confidence, консенсус, разногласия и рекомендации;
- статус `completed`, `partial` или `failed`;
- время выполнения и ссылку на исходный запуск при replay.

Полный отказ всех участников по-прежнему возвращает HTTP 502, но запись со
статусом `failed` сохраняется и доступна в истории.

## Схема данных

Revision 0044 создаёт две таблицы:

- `council_runs` — запрос, статус, агрегаты и итоговый синтез;
- `council_run_members` — упорядоченные результаты отдельных участников.

Участники удаляются каскадно вместе с запуском. При удалении исходного запуска
ссылки последующих replay переводятся в `NULL`, поэтому дочерние отчёты
сохраняются.

Политика хранения записывается в существующую таблицу `settings` с ключом
`council.history.retention`; отдельная таблица настроек не требуется.

## Workspace isolation

Все маршруты истории используют текущий `X-Workspace-ID`:

- Workspace видит только собственные записи;
- запрос идентификатора из другого Workspace отвечает 404 и не подтверждает
  существование записи;
- глобальная история без Workspace отделена от Workspace-записей;
- `workspace_id` в теле запуска не может противоречить заголовку — в этом
  случае возвращается 409.

## API

```tex
GET    /api/council/runs
GET    /api/council/runs/{run_id}
POST   /api/council/runs/{run_id}/replay
DELETE /api/council/runs/{run_id}


Параметры списка:

| Параметр | Назначение |
|---|---|
| `status` | `completed`, `partial` или `failed` |
| `mode` | `universal`, `crypto`, `code` или `documents` |
| `query` | Поиск по тексту вопроса |
| `started_from` | Нижняя граница времени в ISO 8601 |
| `started_to` | Верхняя граница времени в ISO 8601 |
| `limit` | Размер страницы, 1–200; по умолчанию 50 |
| `offset` | Смещение; по умолчанию 0 |

Replay использует сохранённые provider/model, роли, вопрос, режим и модель
председателя. Это новый реальный вызов provider: возможны тарификация,
rate limit или изменение доступности модели. Новый отчёт получает собственный
`run_id` и `replay_of_run_id`.

## Политика хранения

```tex
GET  /api/council/retention
PUT  /api/council/retention
POST /api/council/retention/purge


Значения по умолчанию:

```json
{
  "retention_days": 365,
  "auto_delete_enabled": false,
  "store_member_answers": true,
  "store_token_usage": true
}


- `retention_days` принимает значения 1–3650;
- автоматическая очистка выполняется после сохранения нового запуска только
  при явном включении;
- `purge` сразу удаляет записи текущего Workspace старше настроенного срока;
- `store_member_answers=false` скрывает тексты отдельных участников в новых
  записях, но итоговый синтез продолжает сохраняться;
- `store_token_usage=false` не сохраняет token counters новых запусков;
- изменение флагов не переписывает уже сохранённые записи.

## Интерфейс

В разделе **AI Council** доступны вкладки **Новый анализ** и **История**.
История содержит поиск, фильтры, даты и пагинацию. Карточка показывает полный
сохранённый отчёт или причины полного отказа.

Перед replay интерфейс запрашивает подтверждение и отдельно предупреждает о
моделях, которые текущий каталог считает тарифицируемыми. Удаление необратимо
и также требует подтверждения.

## События и конфиденциальность

Публикуются события:

- `council.history.saved`;
- `council.history.deleted`;
- `council.retention.updated`;
- `council.retention.purged`.

Payload событий содержит только технические идентификаторы, статусы и счётчики.
Вопросы, ответы участников и итоговый текст в Event Bus не публикуются.
